# HTTP security and browser requests

Implemented controls are in `Services/SecurityHeaders.cs`, `EnterpriseAccessMiddleware.cs`, `EnterpriseIdentity.cs` and `IdentityEndpoints.cs`. `SecurityHeadersTests` and `CsrfTests` verify the browser/API contracts; `scripts/browser_smoke.mjs` records `securitypolicyviolation` events throughout the desktop, mobile and simulated private-session flows. `scripts/smoke_widget_csp.sh` renders the actual pinned public widget bundle with wholly intercepted synthetic provider replies.

Every response, including static assets, authentication failures, rate limits and errors, carries enforced Content-Security-Policy, `nosniff`, `Referrer-Policy: no-referrer`, restricted Permissions-Policy, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, COOP `same-origin` and CORP `same-origin`. Production HTTPS replies add one year of HSTS with subdomains. The owner must terminate HTTPS correctly and preserve the request scheme at a trusted ingress; do not trust arbitrary client forwarding headers. HSTS is not emitted on plain HTTP or non-production hosts.

The HTML shell uses fresh cryptographic 192-bit nonces on its two external scripts. Script nonces match each response's enforced policy; HTML is `no-store`. Inline scripts, inline event handlers, inline style attributes, evaluation and framing are disallowed. Interface styles remain external. Metric graphics use SVG dimensions, and the offline interface uses a stylesheet class. The service worker caches only the interface, retains the corresponding cached response headers and never caches authentication or operational data.

Provider browser sources are enabled only for a non-demo deployment with both an ElevenLabs API credential and agent ID. Public mode permits the pinned widget `@elevenlabs/convai-widget-embed@0.19.0`; private modes permit the pinned client `@elevenlabs/client@1.27.0`. Both scripts use SHA-384 SRI, anonymous CORS and the page nonce. The client uses the pinned `@alexanderolsen/libsamplerate-js@2.1.2` audio worklet. Connections permit the provider API/WebSocket origin, a validated provider regional API origin, and the provider's LiveKit transport for public/WebRTC modes. Blob audio/worklet resources are restricted to configured voice mode. Public widget CSS/fonts/images additionally permit Google Fonts and the provider's Google storage path. Other third-party origins remain blocked.

The pinned widget creates theme styles dynamically in its shadow root. CivicOps assigns the style nonce only to insertions into that widget instance's shadow root; the widget's global style helper receives the same nonce through its bundler nonce variable. Its optional third-party dependency monitoring is disabled. A future widget/client upgrade must review network sources, SRI and generated style behavior again. The public-widget smoke verifies archive integrity, SRI, matching nonced theme styles, actual rendered controls, configured global region, disabled optional monitoring and zero CSP/runtime violations. It downloads the pinned public npm archive read-only, launches an isolated synthetic local server, intercepts every provider/dependency request and sends zero provider requests. Run `CIVICOPS_PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs ./scripts/smoke_widget_csp.sh` after a Release build. Live CDN availability, microphones, account settings and provider session operation remain owner validation; offline rendering and private browser doubles do not attest those services.

Cookie-authenticated POST, PUT, PATCH and DELETE requests must carry `X-CivicOps-CSRF` obtained from `GET /auth/status` and the matching HttpOnly CSRF cookie. Login itself requires this token even before authentication. Refresh the status/token after login or identity changes: tokens bind to the authenticated identity and another browser's token is invalid. CSRF failures return safe ProblemDetails with status 400. Session cookies are Secure, HttpOnly, SameSite=Lax and server-side opaque references; non-demo CSRF cookies also require HTTPS.

Explicit bearer service accounts, legacy bootstrap dispatcher/training credentials and provider shared-secret tool authentication are exempt from cookie CSRF by design. They use explicitly supplied credentials instead of ambient browser cookies. A bearer header takes precedence over a cookie and never combines its scopes with cookie roles. Unknown bearer credentials fail closed. Signed provider webhooks use body HMAC validation and replay handling. Public resident intake without a staff session does not use ambient staff authority and remains bounded and rate limited. Cross-origin CORS is not enabled.

New configuration variables: none. The existing demo, environment, ElevenLabs agent/key/session-mode/API-base settings select these controls. All missing provider configuration stays simulated or disabled; no external script/source is enabled by explicit demo mode.
