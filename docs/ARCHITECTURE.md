# CivicOps architecture and invariants

The working application is a .NET 10 Minimal API with a vanilla JavaScript interface, selectable file/PostgreSQL persistence, bounded backend reasoning and two external integration clients. Runtime provider integrations use raw HttpClient; PostgreSQL uses pinned Npgsql. TimeProvider and replaceable handlers make signed webhooks, retry timing and provider responses testable without credentials.

## Intake and bounded reasoning

Forms, Open311 and ElevenLabs tools converge on IncidentCoordinator. It validates lengths, normalizes resident-supplied area, checks the hashed idempotency key and fingerprint, applies deterministic triage plus any Open311 service-code signal, runs agents, and persists a PendingApproval case. The same key/content replays; different content with the same key conflicts.

| Agent | Declared scope | Enforced boundary |
|---|---|---|
| IntakeAgent | Read intake text; draft structured intake | Location remains resident supplied; no inferred consent |
| TriageAgent | Read structured intake; recommend triage | Allowed category/department pairs and priorities only; danger floor |
| DuplicateAgent | Read a heuristic candidate; recommend review | Receives both bounded descriptions; no automatic merge |
| DispatchAgent | Read eligible crews; recommend one | Cannot recommend a crew outside the department or assign it |
| CommsAgent | Read public case status; draft an update | English/Afrikaans/isiZulu templates; no promised ETA; approval required; Afrikaans/isiZulu drafts need native-speaker review |
| AuditLog | Append events and verify their chain | Existing audit events cannot be edited or removed through store mutations |

Each AgentRun stores an input SHA-256 hash, agent name, permissions, actual provider/model/endpoint label, latency, output, confidence, rationale, fallback indicator and a generic error code. External error bodies and credentials are excluded. Resident text is explicitly untrusted data in the prompt. Agent services hold no approval, assignment, sending or calling capability.

The OpenAI-compatible client sends `/v1/chat/completions` with a strict JSON schema, zero temperature and bounded output tokens. Required properties, types, enumerations, maximum lengths, coherent category/department pairing and eligible crew ids are validated in the application. A shared per-decision timeout bounds at most two HTTP attempts; transient failures retry, invalid JSON falls back. Responses are capped at 64 KiB and model content at 8 KiB. The default Qwen3 request disables thinking. Missing endpoint configuration uses deterministic fallback and logs that fact.

Low confidence or disagreement with deterministic triage marks review. Fire, trapped people, live wires and flooding inside a home always floor priority at Urgent. All newly created cases require human approval independently of model confidence. The API records a separate safety-floor run when it overrides a model's priority.

## Human workflow

Approval and crew assignment are separate authenticated operations. Status transitions follow IncidentWorkflow; InProgress requires an assigned crew and durable approval. Client-supplied `approvedBy` labels do not establish identity. The ASP.NET Core OIDC handler maps trusted claims/groups to explicit municipality roles and stores opaque staff sessions server-side. Cookie mutations require CSRF. Scoped service-account and bootstrap bearer hashes use constant-time comparison. DispatcherAccess retains named environment credentials as default-tenant supervisor/dispatcher bootstrap. Authentication runs before dispatch rate limiting; dispatch partitions use the authenticated subject/token hash, anonymous partitions use the transport IP, and every partition includes municipality. A reverse proxy deployment must explicitly configure trusted forwarding rather than trusting arbitrary caller headers.

New resident information or a signed provider reply can flag an already approved/assigned case for another review. A verified dispatcher can approve that review while preserving its current status and assignment. A new hazard cannot silently inherit an earlier approval.

A CommsAgent draft is generated on workflow changes. Only an explicit dispatcher approval publishes a resident comment through Zendesk. Draft approval sends email only when contact consent is recorded and the email service is in outbox mode. Outbound calls additionally require callback consent and configured phone/agent settings. Call intent is persisted before contacting ElevenLabs; an ambiguous failure suppresses automatic retry and needs operator reconciliation.

When status changes, older pending drafts become Superseded. The API refuses approval of a draft from an earlier status. Delivery intent identifies the approved draft, so later status changes cannot replace its recorded text.

Workflow drafting runs outside persistence locks. Explicit expected versions remain strict. A request without an expected version may atomically preserve concurrent Zendesk delivery audit events and ticket metadata only when all other case state and the existing audit prefix match its preparation snapshot. Concurrent human, safety, consent or geographic changes conflict; no model call or automatic workflow retry runs under the store lock.

## Omnichannel intake and human replies

[Channel contracts](../products/civicops/Models/Channels.cs) normalize six native voice/SMS/WhatsApp providers into `InboundMessage`. [ChannelAdapters](../products/civicops/Services/ChannelAdapters.cs) verifies native authentication, receiver/account binding and a fresh trusted-relay envelope; the bounded [loopback relay](../scripts/channel_relay.py) authenticates vendors before signing. Native ingress is disabled without explicit configured mode, HTTPS public base, ingress secret and owner-managed encryption key. Demo uses only authenticated synthetic fixtures and simulated replies.

[ChannelStore](../products/civicops/Services/ChannelStore.cs) persists tenant-specific encrypted contacts, keyed resident/content hashes, per-channel threads, consent/preferences, versions, replay receipts and audit-linked send intents in the selected file/PostgreSQL backend. A key fingerprint fails closed if contact custody changes; readiness verifies state/audit/key integrity across municipalities. Preparation commits before [ChannelService](../products/civicops/Services/ChannelService.cs) calls the existing coordinator outside storage locks. Stable case keys recover interrupted processing without duplicating provider messages. First-contact privacy processing waits for current-purpose consent; no raw native body, audio/video or fetched media is retained.

Dispatch-authorized humans approve each reply with reason, current template/conversation versions and an operation ID. Suppression and purpose gates precede transport construction. Simulation never builds a live request; a configured send makes one bounded attempt, records accepted-unverified/rejected/ambiguous outcome and never automatically retries an uncertain send. WhatsApp free-text/interactive windows use native resident time; outside 24 hours a registered approved-template name is required. Voice callbacks require an explicit request and addressable contact. Unsupported outbound transports remain disabled. Templates and preferences are audited; hourly purge removes expired contact/message/draft text while retaining minimal suppression/idempotency metadata and value-free audit. These controls do not erase historical backups or provider records. [Channel setup, limits and acceptance](CHANNELS.md).

## Conversations and tickets

ElevenLabs receives five server webhook tools, synthetic knowledge and resident/callback agents through an idempotent provisioner. Tool requests use a workspace-secret-backed header, bounded bodies and conversation/turn idempotency. Case mutation tools must match the original conversation; public status lookup uses a case reference and a minimal public update. Post-call requests verify the official timestamp/raw-body HMAC scheme, preserve no audio, attach bounded transcript/analysis metadata, and can recover an unreported issue as a case requiring review. Durable event markers suppress replay.

Zendesk receives case reference as external_id, a private provenance note and consented requester information. Delivery is durable and asynchronous. The worker checkpoints attempts, retries transient errors with exponential backoff and jitter, preserves per-case ordering and exposes permanent failures as dead letters. Provider circuits and bounded timeouts preserve deterministic intake fallback. Reconciliation every five seconds recovers missing case creates, the latest domain-status intent and each approved draft id after a crash. Simulation stores exact request payloads in the selected backend and uses deterministic ticket ids. Signed Zendesk replies append audit events and flag review; they cannot mutate the dispatch lifecycle. CivicOps delivery markers prevent echoes.

The remote Zendesk external_id search is not a uniqueness constraint. Search indexing and uncertain HTTP responses leave a live duplicate-creation risk. The PostgreSQL transactional outbox commits a claim/lease before provider delivery and releases its SQL transaction during the call. Delivery remains at least once after lost responses or expired leases; downstream deduplication and operator reconciliation remain necessary. Comment deduplication and external-id reconciliation have a bounded 20-page budget and fail closed when it is exceeded.

## Persistence, audit and updates

`CIVICOPS_STORAGE=file|postgres` selects `DurableStorage`; file is the zero-configuration default. File mode uses an exclusive process lease, flushed temporary files and atomic replacement. PostgreSQL is authoritative for every durable entity, retaining versioned snapshots and relational incident/audit/outbox projections. Embedded, checksum-verified SQL migrations run at startup under an advisory lock. Nested stores join the same transaction; case, contact, audit and delivery-intent writes commit or roll back together. Fresh database reads and the advisory transaction lock preserve idempotency and optimistic versions across instances. The current coarse lock serializes all SQL snapshot operations; complete snapshots are still read/serialized, and production throughput requires measurement. [Storage, migration/import and shared contracts](operations/STORAGE.md).

The tenant audit chain includes cases, idempotency hashes, approvals, assignments, agent runs, drafts and mirrored administration/training events. The audit stores a SHA-256 hash of the previous entry and the serialized entry content. `/api/audit/verify` recomputes the sequence and checks each retained case against its latest recorded state hash. It detects modified/deleted/reordered entries and modified case snapshots; the store refuses further mutations after detecting tampering. The PostgreSQL audit projection also rejects a shortened tail or replacement of an existing entry.

Hash chaining is tamper evidence, not independent proof: a host administrator or database superuser can rewrite storage. Auditor-role signed exports contain JSONL plus an HMAC-SHA256 manifest authenticating the tenant, counts, head and exact file checksum; an offline verifier checks the original chain. An owner signing key is required, and unconfigured demo export is explicitly disabled. The implemented local target creates exclusive, read-only artifacts; host-enforced WORM and external anchoring are not attested. S3 Object Lock/Azure immutable targets are documented-only. [Audit export and trust boundaries](operations/AUDIT_EXPORT.md). File atomic replacement does not provide directory fsync or a transaction across separate files. [Tested backups/restores and proposed RPO/RTO](operations/BACKUP_RESTORE.md) cover both backends; production scheduling, retention, key custody and disaster recovery remain owner responsibilities.

The authenticated SSE stream sends refresh events without case payloads; clients fetch fresh data with authorization. Polling is the fallback. Service workers cache application shells only; operational requests stay network-only. The crew PWA separately holds bounded assigned-job snapshots and pending edits in worker-scoped IndexedDB, with private-state clearing on sign-out/authorization loss. The public reference view excludes resident contact, text, location, transcripts, agent outputs, approvals and internal audit actors. Dashboard detail is authenticated.

The authenticated `/api/evidence/export` projection exposes case status and bounded AI provenance such as provider, input hash and confidence. It omits descriptions, contact and raw transcripts. It supplies judge evidence without exporting the private operational snapshot.

OpenTelemetry traces, metrics and redacted structured JSON logs carry request correlation/trace IDs; exporter configuration and signals are described in [observability](operations/OBSERVABILITY.md) and [proposed SLOs](operations/SLO.md). `/health/live` reports process liveness; `/health/ready` checks storage/migrations/outbox thresholds and tenant geo-store integrity, and reports simulated, unverified or unavailable providers as degraded. `/healthz` remains compatible. Production dashboards, alert delivery and actual municipal SLO measurements remain owner-pending.

## Geographic operations

Authenticated `/api/v1/map` routes project tenant-local municipalities, wards, cases, synthetic crew positions, structured hazards and assets as GeoJSON. Cases acquire optional volunteered coordinates only with a separate explicit sharing choice and recorded coordinate-purpose notice. Pure polygon geometry assigns jurisdiction, including exterior edges and excluded holes, inside a validated South African regional envelope. Named authorized human overrides are version-checked and audited. No textual address is turned into an invented point.

The map has bounded paged layers, tenant/query ETags, incident/hazard grid aggregation and a bounded metadata-only refresh SSE stream with heartbeats and finite authenticated connections. It renders pinned local Leaflet/markercluster assets, a repository canvas heat layer and outline fallback without a tile connection. The configured credential-free HTTPS tile host is the only extra CSP image origin. Tile failure does not remove jurisdiction geometry; server failure is explicitly stale/offline, and loss of authorization clears cached staff map state.

Geo storage has a tenant-specific integrity chain, independently validated by readiness. Case-backed map projections use fresh integrity-verified snapshots and fail closed on tampering, while existing queue/audit inspection remains available. Automatic hourly retention removes expired synthetic crew positions, hazards and report coordinates; projections hide expired records before purge. Round 10 adds supervisor-only crew positions through a separate shift/consent-verified crew store, without opening generic geo ingestion. Nearest-crew suggestions require fresh positions and current workforce eligibility, and use straight-line distance. Existing case review/approval, supervisor hazard checks, named human confirmation and audit still gate assignment. Camera frames, biometric identification, person scoring and predictive policing are excluded. [Map configuration and limits](MAPS.md) and [responsible AI guards](RESPONSIBLE_AI.md) define the operating boundary; real municipal geometry/assets and agency integrations remain owner-pending or future engineering.

## Crew clients, identity and on-shift location

The Kotlin/Compose Android client and installable `/crew/` PWA use `/api/v1/crew`. Assigned job detail exposes hazard/PPE/certification/procedure context; named worker status, notes and sanitized photo evidence require the current assignment, expected job version and an operation ID. Job metadata and idempotency receipts join the incident's durable audited mutation. Photo bytes have separate bounded storage and retention, with orphan cleanup after interrupted writes. The server strips image metadata even when a native client recorded a per-photo location choice; no detector/video feed or identification processing is provided.

Supervisors issue short-lived, single-use device pairing codes for an existing tenant worker. Exchanges grant hashed-at-rest, expiring and revocable crew credentials. Native OIDC uses AppAuth code/PKCE in the system browser and a configured public-client audience; the server validates issuer/signature/audience/expiry and a one-use server nonce challenge before issuing the same crew-scoped credential. Trusted tenant, crew and worker bindings are checked against municipal workforce records. Configuration without the required native audience remains honestly disabled. Staff browser OIDC continues to use the existing secure session and CSRF controls. Live issuer registration and mobile device behavior remain owner validation.

Crew state records server-issued shift/consent identifiers and notice text/version. Readiness independently verifies its snapshot/audit integrity across all tenants without granting or logging data access. The server rejects and audits off-shift, expired, withdrawn, wrong-device or invalid-consent location requests independently of client assertions. Raw points live in tenant/worker/day documents, with bounded idempotent batches and location/accuracy/time validation. Current positions disappear at shift end/withdrawal/expiry; automatic raw-data purge retains tenant-day sample counts without worker association. Workers may read/export their own retained raw history; supervisor map projections expose the latest consented crew point and last-seen age. Defaults are 60-second sampling, 100-metre accuracy, 30-day raw retention and a 12-hour maximum shift, capped earlier by credential expiry; policy changes are bounded and require a named supervisor reason.

Android uses Room and WorkManager for retrying job edits and a visible private location foreground service; tokens use Android Keystore-backed encryption and app backups are disabled. Tracking never starts from boot or silently resumes after process restart. The PWA uses IndexedDB and its own service-worker cache, collects only in a visible open page, and stops on hide/offline/end/withdrawal/expiry. Both clients stop collection locally when a privacy change cannot yet reach the server. Revoked credentials and rejected location gates stop sharing. Offline job conflicts require deliberate review instead of an automatic version override. SOS records a tenant-bound control-room alert after deliberate confirmation. SMS and WhatsApp panic phrases open that alert; voice stays emergency-number information. CivicOps does not call, message or dispatch responders. [Crew guide](CREW_APP.md), [native build evidence](ANDROID_BUILD.md) and [responsible AI controls](RESPONSIBLE_AI.md) distinguish local implementation from municipal production acceptance.

## Deployment and proof

The digest-pinned Dockerfile publishes the app into ASP.NET 10.0.12 Ubuntu chiseled-extra, runs as UID/GID 1654 with a read-only root filesystem, and uses a package-free .NET helper to check `/health/ready`. Writable Data/tmp mounts are explicit; image/runtime execution remains unverified because this box has no Docker daemon. The production Compose definition adds PostgreSQL and optional telemetry/ROCm vLLM profiles; the root Compose definition retains the synthetic file demo. The statically tested Helm chart provides probes, resource/security limits, TLS ingress, network policy and migration hooks. It rejects more than one application replica and an HPA maximum above one, and uses Recreate to avoid overlapping process-local sessions/SSE/quotas during upgrades. Shared PostgreSQL makes durable HTTP state portable, while those remaining local controls prevent a fully stateless multi-node release. [Deployment, scale guards and rollout limits](operations/DEPLOYMENT.md) distinguish implemented-and-tested controls from future distributed session/quota/SSE work.

The resident desk uses packaged English, Afrikaans and isiZulu resources shared with server consent/status messages and deterministic drafts. The chosen report language controls privacy-minimal status lookups. Afrikaans/isiZulu content is machine-drafted and needs native-speaker and municipal review before production. Live ElevenLabs presets remain English/Afrikaans; simulated chat can use all three UI languages, and live isiZulu voice is owner/provider validation. [Accessibility and language review](ACCESSIBILITY.md) records automated evidence and the manual gaps. [The complete OpenAPI contract](api/README.md) covers every mapped method, its projections/security, synthetic examples and shared errors; its committed snapshot is enforced by route-coverage and synchronization tests.

TLS, public ingress, explicitly trusted proxy networks, real issuer application registration/MFA and retention remain deployment responsibilities; staff identity and role/tenant policies are implemented and locally tested. Development and CI use only synthetic data and fake handlers. See [AMD deployment and measurement boundaries](operations/AMD_VLLM.md), [ELEVENLABS_SETUP.md](ELEVENLABS_SETUP.md), [ZENDESK_SETUP.md](ZENDESK_SETUP.md) and [SECURITY.md](../SECURITY.md) for setup and owner validation.

## Enterprise identity and tenant partitions

Every mapped endpoint has one named policy from `PermissionMatrix`. `TenantContext` binds requests from authenticated claims or resident host/path; `TenantStore` owns routing metadata. Stores keep independent tenant partitions and durable logical paths; PostgreSQL reads fresh state rather than trusting process caches. Background recovery, retention and delivery iterate tenant leases. Streams capture their subscriber tenant. Legacy default migration preserves historical hashes and rejects rebinding into another tenant. Identity credentials and catalogue revisions have recoverable per-tenant chains mirrored into incident audit. Admin catalogue changes become active through a request-local catalogue used by service discovery, schema prompts, routing, workforce and training. PostgreSQL transaction/concurrency contracts are tested across instances; staff sessions, SSE notifications and rate-limit counters remain process-local. No distributed transaction with an external provider, external audit anchor or multi-instance session store is claimed. [Exact matrix and identity configuration](RBAC.md).
