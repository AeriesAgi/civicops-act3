# CivicOps OpenAPI contract

[`openapi.json`](openapi.json) is the reviewed OpenAPI 3.1 snapshot of the live `/openapi.json` endpoint: **140 paths, 150 operations and 191 component schemas**. Every mapped HTTP method is covered, including the document endpoint. The ten existing portable training schemas remain published, with two closed map schemas, the closed [crew location batch schema](../schemas/crew-location-request.schema.json), and closed SOS create/location/action/USSD contracts. Grouped routes use canonical paths without trailing slashes; ASP.NET accepts their equivalent trailing-slash form.

Success bodies include privacy-minimal resident and staff projections, training/catalogue records, identity/administration, provider readiness, health, signed audit downloads and manually parsed provider requests. JSON requests/responses have synthetic examples. ZIP downloads use `application/zip`; SSE uses `text/event-stream`. Dashboard, map and training streams send `ready` or heartbeat events and empty-data change events. The SOS stream sends `event: sos` with the current alert JSON. SSE clients refresh authoritative state after reconnect because there is no durable replay. Catalogue reads describe ETag/304 behavior, and OIDC login/logout describe redirects.

The twelve `/api/v1/map` operations cover public-safe configuration for authenticated staff, bounded tenant-local GeoJSON layers/wards, aggregate heat, metadata-only SSE, crew qualification detail, human-confirmed nearest dispatch, audited jurisdiction override, strict reviewed hazard intake, versioned polygon administration and explicit demo seeding. GeoJSON uses `application/geo+json` with ETag/304 on read collections. Layer queries document bounding box, selected layers, changed-since, page and limit. Heat accepts only cases/hazards and 24h/7d. The map SSE sends 15-second heartbeats, expires after five minutes and reconnects through authorization; it has no position payload or replay. Shared report coordinates are optional, purpose-labelled and bounded to longitude 16–33 / latitude −35–−22. Latest crew pings are visible only to supervisors/admins while the worker has a current consented shift, an unexpired device and current workforce binding; raw histories are never map features. [Map operating limits](../MAPS.md) and [responsible AI guards](../RESPONSIBLE_AI.md).

The 27 `/api/v1/crew` operations implement assigned jobs, versioned status/notes/sanitised photos, supervisor evidence review, shift start/end, explicit revocable purpose consent, idempotent batched locations, own paged history/full JSON export, tenant policy, retention, pairing/revocation and native OIDC sign-in. A location retry is rejected after shift end/withdrawal/expiry even when its original batch was accepted. Batches contain 1–100 points from one UTC day, at the tenant interval (one-second timer tolerance above the 15-second minimum). Policy bounds are 15–600 seconds, 5–1000 metres, 1–30 retention days and 1–12 shift hours. Worker completion is a report awaiting the existing dispatcher resolve/review workflow. The crew SOS route now records the same bounded SOS alert contract; it requires the deliberate client confirmation and never dispatches or contacts responders. [Crew app and privacy model](../CREW_APP.md).

The SOS operations add idempotent resident/crew triggers, a bounded follow-up location window, human-only acknowledge → assess → dispatch → resolve/false-alarm actions, tenant-scoped queue/detail/SSE reads, simulated SMS/WhatsApp keyword intake, and a simulated USSD adapter. All responses retain a tenant-bound resident contact hash rather than raw contact data. The control room records escalation targets and audit reasons; no provider message, emergency call, or automatic dispatch is performed. See the [SOS operating contract](../SOS.md).

Resident/Open311 intake examples are submitted in automated tests against the synthetic baseline catalogue. Other examples demonstrate schema formats: discover current municipality catalogue/record IDs, supply current versions and future credential-expiry dates, and use actual prerequisite training records before authorized mutations. Credential fields stay blank. Merely copying an example never establishes authorization or a completed lifecycle.

Authentication is explicit per operation. Public/resident routes allow anonymous residents; staff APIs use an opaque `__Host-CivicOps-Session` cookie, or an explicitly permitted bootstrap/service bearer. Service tokens are municipality-bound and checked for the route's scope. Staff cookie writes require `X-CivicOps-CSRF`, obtained with its cookie from `/auth/status`; local demo/bootstrap login forms also require it. Training credentials remain scoped to training. Native channel webhooks require vendor authentication plus a fresh trusted-relay HMAC, and existing Zendesk/ElevenLabs webhook schemes remain required; a bearer token never substitutes for the webhook signature.

The `oidc` security scheme publishes an **owner-specific discovery placeholder**, not a configured issuer or a working identity service. Configure `CIVICOPS_OIDC_AUTHORITY`, start `/auth/login`, and complete authorization code + PKCE to obtain the staff cookie. Issuer ID/access tokens are not accepted as CivicOps service bearer tokens. Native sign-in uses a separately registered public `CIVICOPS_CREW_OIDC_CLIENT_ID`, a one-use five-minute server nonce challenge, and trusted HTTPS discovery/JWKS validation of signature, issuer, audience, expiry and mapped municipality/crew/worker claims. CivicOps accepts exactly one native audience and requires any `azp` to be a single matching string; additional audiences and repeated audience/authorized-party claims fail closed. This deliberately restricts the audience policy permitted by [OIDC Core ID-token validation](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation). The trusted identity must match an explicitly requested municipality before any credential or grant is persisted. Rejections consume the nonce and create a value-free access audit in the requested municipality. `/api/v1/crew/auth/oidc` exchanges that ID token for a hashed, scoped, expiring and revocable CivicOps crew device token. Supervised pairing is the alternative: one-use 40-bit code, ten-minute expiry and the existing authentication quota. Device credentials last at most eight hours and can access `crew:self` operations plus `sos-trigger` for their own alert. They cannot dispatch or read the control-room queue. Live municipal issuer validation remains owner-pending. No real token or deployment-specific secret is included in this contract.

Error contracts cover shared bounded-input, authentication/authorization, isolation, conflict, content-type, quota, storage and provider failures. These cross-cutting errors are possible responses, not a claim that every business handler emits every listed status. Most errors use RFC 9457 problem details; documented middleware paths can return an empty body or a JSON `error`. Variant callback/session/tool/webhook responses describe their conditional fields. Extensible provider-analysis/model JSON remains explicitly open rather than claiming an unsupported closed schema.

The round-11 channel operations cover authenticated inbox/templates/readiness/metrics, reviewed sends/admin edits/purge, demo-only signed fixtures and native verified provider ingress/WhatsApp challenge. Native Twilio form bodies and TwiML responses are documented separately from JSON; provider HTTP bodies are bounded but remain extensible, while normalized/admin DTOs reject unknown fields. [Provider headers, relay freshness and setup](../CHANNELS.md).

Regenerate and check the artifact after changing routes, models or projections:

```bash
export PATH=$HOME/.dotnet:$HOME/.local/bin:$PATH
export TMPDIR=/workspace/civicops/tmp

dotnet build -c Release
./scripts/export_openapi.sh
./scripts/lint_openapi.sh --install
dotnet test -c Release --no-build --filter 'FullyQualifiedName~OpenApi'
```

The exporter starts an isolated local Release application in explicit synthetic demo mode and fetches only its document; it makes no provider requests. A test compares the saved JSON structurally with the live document, so a stale snapshot fails the normal suite. Tests also compare every actual mapped method/route against the document and permission matrix, traverse every local reference, check request/success/error examples and schemas, and verify privacy/security/media behavior and deterministic secret-independent generation.

Spectral runs the official recommended OpenAPI rules through pinned `@stoplight/spectral-core` **1.24.0** and `@stoplight/spectral-rulesets` **1.23.0**, with patched `lodash` **4.18.1**, installed only in `$TMPDIR/openapi-lint-tools`. Each lint run also requires a clean `npm audit --audit-level=low`. The CLI's glob dependency currently has an unfixable braces advisory, so the wrapper uses the official API without that dependency chain. The only disabled rule is unused components: the portable training schemas are intentionally retained for extension clients. `CIVICOPS_SPECTRAL_TOOLS_DIR` can select another verification-tool directory; it is not an application setting.

The existing **11 OpenAPI tests** and **5 map-contract tests** cover published intake/Open311 examples, actual GeoJSON responses, tuple coordinates, rejected unknown fields and map configuration/query/approval fields. Current run results and **Spectral/npm advisory gates** are recorded in [verification](../VERIFICATION.md). Documentation/runtime schemas do not certify deployed ingress, provider accounts, municipal SSO or AMD infrastructure; those remain owner validation. Afrikaans/isiZulu resident strings are machine-drafted and require native-speaker review before production.
