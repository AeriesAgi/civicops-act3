# Owner checklist: ElevenLabs and Zendesk

The synthetic demo needs no provider credentials. `CIVICOPS_DEMO_MODE=true` forces simulated ElevenLabs and Zendesk transports even if credentials are present. This round verified documentation, request JSON, session handling and reconciliation with fake HTTP; no live provider call, provision, phone call or account change was made. Use synthetic reports until the owner completes and validates this checklist.

## Numbered setup

1. **Prepare the CivicOps runtime.** Deploy behind HTTPS; set `PUBLIC_BASE_URL` to the public origin, `CIVICOPS_DATA_DIR` to a private persistent directory, staff OIDC or administrator bootstrap identity (see [RBAC.md](RBAC.md)), and `CIVICOPS_DEMO_MODE=false` only in the intended live runtime. Export values through a private environment manager: CivicOps does not load `.env` files. Keep keys and resident data out of Git, browser configuration and command history.
2. **Create a restricted ElevenLabs key.** In **Developers → API Keys**, create an application key in the existing grant workspace. Provisioning needs **Conversational AI read and write** (`CONVAI_READ`, `CONVAI_WRITE` in the official scope guidance); grant access to the CivicOps agents, tools, knowledge documents and any connected phone number. Store the actual key in `ELEVENLABS_API_KEY`. A separate runtime/check key needs read/session access and outbound-call access only if callbacks are enabled; remove provisioning writes after setup. Set a credit quota and, when the deployment has fixed egress, IP restrictions. Leave `ELEVENLABS_API_BASE` blank for `https://api.elevenlabs.io`, or set the workspace's supported regional HTTPS API origin. Scope labels can differ in the UI; confirm permission against the exact endpoint table below. [API keys](https://elevenlabs.io/docs/overview/administration/workspaces/api-keys), [official scope guidance](https://github.com/elevenlabs/skills/blob/main/agents/references/using-procedure-api.md).
3. **Issue a municipality-bound service account for the tools.** Sign in as an administrator and open **Administration → Service accounts**. Create `ElevenLabs tools` with only `tools:invoke` and a reviewed expiry. Copy the token from its one-time result; CivicOps stores only its SHA-256 hash. In **Agents → Settings → Secrets**, create `CivicOps tool authentication` containing the full header value `Bearer ` followed by that token. Copy the secret identifier to `ELEVENLABS_WORKSPACE_TOOL_SECRET_ID`. Each checked-in tool now uses `request_headers["Authorization"] = {"secret_id":"…"}`; conversation headers use `{ "variable_name":"system__conversation_id" }`. Keep the token in the provider workspace secret and trusted server configuration, never a resident browser. Rotate in CivicOps, replace the workspace value during the configured 0–60 minute overlap, then revoke when retiring access. `CIVICOPS_ELEVENLABS_TOOL_SECRET` with `X-CivicOps-Tool-Secret` remains a default-municipality legacy bootstrap path, and new provisioning uses service accounts. Caller ID never supplies consent. [Workspace secret](https://elevenlabs.io/docs/eleven-agents/api-reference/workspace/secrets/create), [bearer tool authentication](https://elevenlabs.io/docs/eleven-agents/customization/tools/webhook-tools), [CivicOps permissions](RBAC.md).
4. **Create the signed post-call webhook before provisioning.** In **Agents → Settings → Webhooks** (workspace **Settings → Webhooks** in some UIs), create the HTTPS target `PUBLIC_BASE_URL` + `/api/channels/elevenlabs/post-call`. Copy its HMAC signing secret into `ELEVENLABS_WEBHOOK_SECRET` and its identifier into `ELEVENLABS_POST_CALL_WEBHOOK_ID`. The provisioner attaches this identifier to both agents at `platform_settings.workspace_overrides.webhooks.post_call_webhook_id`, enables `transcript` and `call_initiation_failure`, chooses JSON format, and leaves turn transcripts available for dispatcher review. Disable audio events. Provider event settings say `transcript`; delivered event type is `post_call_transcription`. CivicOps ignores audio events and stores no audio. [Post-call webhooks](https://elevenlabs.io/docs/eleven-agents/workflows/post-call-webhooks), [Create Agent webhook fields](https://elevenlabs.io/docs/eleven-agents/api-reference/agents/create).
5. **Choose the browser channel and allowlist.** Set `ELEVENLABS_WIDGET_ALLOWED_HOSTS` to comma-separated hostnames, without schemes, ports or paths. Set `ELEVENLABS_SESSION_MODE=public` for the supported public widget, `signed-url` for private WebSocket, or `webrtc` for private WebRTC. Private modes set resident-agent `auth.enable_auth=true`; the callback agent is always private. The public resident session endpoint is rate limited, returns `Cache-Control: no-store`, and exposes only a short-lived credential for the configured resident agent. Private *agent* authentication does not identify the resident; a staff-only deployment must protect the app's ingress/session route. [Agent authentication](https://elevenlabs.io/docs/eleven-agents/customization/authentication), [widget](https://elevenlabs.io/docs/eleven-agents/customization/widget).
6. **Choose voice, languages and knowledge.** Optionally set a workspace-approved `ELEVENLABS_VOICE_ID`. Review the synthetic Markdown under `products/civicops/elevenlabs/knowledge/` against the actual municipality before real intake. Provisioning combines the three files into an immutable, content-addressed text document and attaches a `{type:"text",name,id,usage_mode:"prompt"}` knowledge locator to each agent. English `en` is the default; the Afrikaans `af` preset supplies Afrikaans language and a reviewed first message, including callback-specific wording. `language_detection` and `end_call` are built-in system tools. The checked-in TTS model is `eleven_v4_turbo`. Have a fluent Afrikaans reviewer validate pronunciation, transcription and safety wording; isiZulu remains unconfigured and unverified. [Language](https://elevenlabs.io/docs/eleven-agents/customization/voice/customization/language), [knowledge](https://elevenlabs.io/docs/eleven-agents/customization/knowledge-base).
7. **Optionally route ElevenLabs' conversation model to AMD.** Set `CIVICOPS_LLM_PUBLIC_URL` to the full protected HTTPS Chat Completions endpoint, and `CIVICOPS_LLM_MODEL` to the served model identifier. If the endpoint requires a bearer credential, create a second ElevenLabs workspace secret containing that credential and set its identifier in `ELEVENLABS_WORKSPACE_LLM_SECRET_ID`. Use `--llm amd` in the provision/check commands. The exact block is `llm:"custom-llm"`, `custom_llm:{url,model_id,api_type:"chat_completions",api_key:{secret_id}}`; no secret value enters the plan. The endpoint must support streaming and tool calls. Backend agent reasoning separately uses `CIVICOPS_LLM_BASE_URL`, `CIVICOPS_LLM_API_KEY`, `CIVICOPS_LLM_PROVIDER_LABEL`, and optional `CIVICOPS_LLM_TIMEOUT_MS`. Post-call analysis is provider analysis; no AMD measurement is claimed. [Create Agent custom LLM](https://elevenlabs.io/docs/eleven-agents/api-reference/agents/create).
8. **Review and apply the agents-as-code plan.** Run the dry-run command below; it sends no HTTP. The optional `--json` plan is machine readable and matches reviewed golden fixtures. After reviewing the concrete plan, the owner can run `--apply`; that command creates/updates external resources. It resolves dependency IDs and stores only resource identifiers at `CIVICOPS_DATA_DIR/elevenlabs-provision-state.json`. Existing unique names are discovered through bounded paginated GETs and updated with PATCH; ambiguous names fail. Copy the printed resident and callback identifiers into `ELEVENLABS_AGENT_ID` and `ELEVENLABS_CALLBACK_AGENT_ID`. No apply was executed during this round.
9. **Check remote drift explicitly.** Run `elevenlabs provision --check` with the same configuration and `--llm amd` if used. It uses only GETs for tools, knowledge metadata/content and agents; reads saved identifiers or discovers names; never rewrites state or provider config. It reports missing resources and differing CivicOps-managed field paths without printing values or credentials. Exit code is `0` for no drift, `1` for drift/missing resources, `2` for missing configuration or failed validation/transport. `--check` and `--apply` cannot be combined. Webhook attachment is compared when `ELEVENLABS_POST_CALL_WEBHOOK_ID` is configured. This verifies configuration, not a successful end-to-end conversation.
10. **Validate the browser privately with synthetic input.** Public mode loads the widget only when configured. Private mode loads pinned official `@elevenlabs/client` version `1.27.0` only when configured, gets its short-lived credential from CivicOps, then calls `Conversation.startSession({signedUrl,connectionType:"websocket"})` or `Conversation.startSession({conversationToken,connectionType:"webrtc"})`. The conversation token API returns both `token` and `conversation_id`; a signed URL is not a WebRTC token. Microphone access follows an explicit resident action. Stop uses `endSession`; text uses `sendUserMessage`. With no configured provider the simulated chat invokes the same CivicOps tools. Test English/Afrikaans report → confirmed reference → post-call signature → dispatcher alert/review before claiming a live channel. [Official JavaScript SDK](https://elevenlabs.io/docs/eleven-agents/libraries/java-script), [signed URL](https://elevenlabs.io/docs/eleven-agents/api-reference/conversations/get-signed-url), [conversation token](https://elevenlabs.io/docs/eleven-agents/api-reference/conversations/get-webrtc-token).
11. **Optionally connect an existing phone number.** In the agent's **Phone numbers** channel, connect the workspace's existing Twilio number or SIP trunk and route inbound calls to the resident agent. Put its `agent_phone_number_id` in `ELEVENLABS_AGENT_PHONE_NUMBER_ID`, choose `ELEVENLABS_PHONE_PROVIDER=twilio` or `sip-trunk`, and optionally set the private human destination `ELEVENLABS_TRANSFER_PHONE`. Blank phone configuration disables callbacks; blank transfer configuration omits the transfer tool. Both outbound APIs receive `{agent_id,agent_phone_number_id,to_number,conversation_initiation_client_data:{dynamic_variables}}`; Twilio uses `/v1/convai/twilio/outbound-call`, SIP uses `/v1/convai/sip-trunk/outbound-call`. Only a dispatcher with a stable `Idempotency-Key` can request a callback, and recorded contact consent, callback consent and a phone are required. A lost response does not automatically retry a call: reconcile conversations before a new logical request. [Twilio](https://elevenlabs.io/docs/eleven-agents/api-reference/integrations/twilio/outbound-call), [SIP](https://elevenlabs.io/docs/eleven-agents/api-reference/sip-trunk/outbound-call).
12. **Configure Zendesk separately.** Set the account label in `ZENDESK_SUBDOMAIN`; use an authorized OAuth access token in `ZENDESK_OAUTH_TOKEN` (preferred), or an eligible existing API token with `ZENDESK_EMAIL` + `ZENDESK_API_TOKEN`. OAuth takes precedence. Create the signed return webhook/trigger described in [ZENDESK_SETUP.md](ZENDESK_SETUP.md), targeting `PUBLIC_BASE_URL` + `/api/channels/zendesk/webhook`, and set `ZENDESK_WEBHOOK_SECRET` from its signing secret. Run the explicit `zendesk --check` command; it performs only `GET /api/v2/users/me.json` and does not print the user's identity. Connectivity is never checked at startup. Verify synthetic ticket creation, private provenance notes, consent-gated requester data and human-approved public comments in the owner's account before showing a live Zendesk claim.


## Endpoint permissions and request contracts

| Feature | Owner key access / protocol |
|---|---|
| Provision | Agents/tools/knowledge list/read + create/update; apply is explicit |
| Reconcile | GET tools, agents and knowledge metadata/content; no writes |
| Browser sessions | GET signed URL or token with server-only `xi-api-key`; credentials are never cached |
| Callbacks | Connected number + outbound-call access; dispatcher approval and resident consent |
| Resident tools | POST `report_incident`, `lookup_case_status`, `add_case_information`, `request_human_handoff`, `list_service_categories`; municipality-bound `tools:invoke` service-account bearer via workspace secret, bounded body and stable conversation/turn identity |
| Post-call | HMAC SHA-256 over `<timestamp>.<raw UTF-8 body>`, header `ElevenLabs-Signature: t=<unix>,v0=<hex>`; 30-minute age limit and 30-second future limit |
| Zendesk check | Authorized users read (`GET /api/v2/users/me.json`); OAuth bearer or legacy Basic `{email}/token:{token}` |
| Zendesk delivery | Tickets/search/comments read + ticket create/update; public comment only after human approval |

For multiple municipalities, provision separate agent/tool secrets with the intended tenant account. Use the corresponding resident host or `/m/{slug}/api/channels/elevenlabs/post-call` for signed callbacks; a body municipality field is never trusted. Zendesk webhooks may also use a scoped `zendesk:webhook` account in addition to their required signature. Outbound provider credentials remain instance configuration; distinct live provider workspaces per municipality are owner deployment configuration, not a verified per-tenant transport feature.

Post-call receipts are durable and reject changed-body replays. Transcripts, bounded summaries and declared data collection remain dispatcher-only; contacts/caller-number metadata never enter public status. Danger in resident turns or collected hazards floors priority at Urgent and requires human review; generic assistant safety wording alone does not mark every report urgent. No provider agent can approve, assign or guarantee an ETA. Voice recording is disabled; audio is deleted; provider retention is seven days. Local retention is configured separately with `CIVICOPS_RETENTION_DAYS`; its purge scope and privacy policy must be validated before a resident pilot.
