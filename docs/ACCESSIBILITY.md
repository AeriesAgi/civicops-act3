# Accessibility and resident languages

CivicOps targets **WCAG 2.2 Level AA** for the resident desk, control room and administration console. This is an implementation and local test statement, not an independent conformance certificate. Automated checks cannot establish full conformance or the accessibility of a municipal identity provider, embedded provider interface or resident voice service.

## Implemented controls

The interface has a skip link, landmarks and associated labels, native keyboard-operable forms and disclosure controls, descriptive button names, visible focus, minimum 24 CSS-pixel control targets, readable status badges, and polite live regions for report results, chat and service degradation. The operating-system theme selects light or dark colours. Reduced-motion preferences disable the view entrance animation. Inputs preserve drafts on failed/offline requests, double submissions are guarded and retries retain their idempotency keys. Focus outlines have room inside scrolling records, chat and queue containers; no fixed banner covers focused controls.

Resident labels, help, placeholders, accessible names, purpose notice and deterministic updates use shared packaged resources in [`wwwroot/locales`](../products/civicops/wwwroot/locales). The language switcher offers English (`en`), Afrikaans (`af`) and isiZulu (`zu`), updates document/section language and the intake preference, and persists only that language preference locally. Staff sections remain explicitly `lang="en"`; their static text and dynamic labels/messages have English resource keys ready for translation. Municipal catalogue content, staff-entered data and provider transcript text retain their original language.

The Live map combines priority colours with distinct shapes, status glyphs, labelled layer/time/search controls, keyboard ward summaries and a same-page feature browser. Pins retain their geographic positions, so dense markers can overlap. The [W3C target-size explanation](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) explicitly allows the essential geographic-pin spacing exception and encourages equivalent controls. Map QA retains raw axe reports, accepts only this specific geographic-target finding, and separately verifies complete same-page alternatives with named keyboard-operable targets at least 24 CSS pixels. Other target-size failures and all other axe rules still fail. This exception is not an independent accessibility certification; assistive-technology and high-contrast manual review remain pending.

**Afrikaans and isiZulu strings are machine-drafted and require native-speaker review before production.** The UI displays that warning. The municipal Information Officer must approve translated purpose notices. Consent receipts store the exact packaged notice and purpose in the language selected when the resident submits, with the existing notice version. Public status follows the report's stored preference, and deterministic communications remain subject to human approval. isiZulu arrival-promise phrases have local safety tests; this heuristic is not a substitute for reviewing model-generated communications.

The ElevenLabs assets retain English/Afrikaans presets. Private starts pass the selected supported language to the browser client; public widget configuration uses that language. The server advertises `en/af/zu` for simulated chat and `en/af` for live voice. Selecting isiZulu in a live configuration hides the live channel, explains that it is not configured or verified, and keeps the form available. No isiZulu voice capability or live language quality is claimed: current [ElevenLabs model documentation](https://elevenlabs.io/docs/overview/models) must be checked for the deployment's actual model and account. Dubbing language coverage does not attest Conversational AI support.

## Automated verification

Run the existing browser smoke with pinned Playwright and axe-core **4.11.0** installed in the tools directory only:

```bash
npm install --prefix "$TMPDIR/browser-tools" --no-audit --no-fund --ignore-scripts playwright-core@1.64.0 axe-core@4.11.0
CIVICOPS_PLAYWRIGHT_MODULE="$TMPDIR/browser-tools/node_modules/playwright-core/index.mjs" ./scripts/smoke_browser.sh
```

The browser harness injects axe through the automation context. The application never loads axe, and its strict CSP remains active. CI installs the same pinned QA dependencies and runs npm advisory checks. `CIVICOPS_AXE_CORE_PATH` is an optional test-only override; by default axe resolves next to the configured Playwright module. No application environment variables are added.

Run `./scripts/smoke_map.sh` for the separate map workflow/accessibility checks. It uses the same pinned browser tools and a throwaway explicit-demo server with tiles disabled. Evidence goes to `$TMPDIR/map-browser-smoke`; only `CIVICOPS_UPDATE_MEDIA=1` updates the four tracked map captures. The smoke blocks external requests and fails if map code implicitly calls browser geolocation. It checks offline fallback, clustering, feature controls, aggregate heat, human dispatch and clearing map state when authorization is lost.

Round 9 map verification passed **62 checks and four axe scans**. Both mobile scans had zero native violations. Dark/light desktop native reports each had one target-size rule containing **23 / 11 geographic-pin nodes**; separate annotations verify each pin's corresponding controls and every cluster's underlying members. All **167 feature alternatives** had names, keyboard focus and targets at least 24 CSS pixels. There were zero unexcepted violations, CSP violations, runtime errors or external requests. The original browser suite separately passed **169 checks and 15 scans with zero native A/AA violations**. The earlier round-7 results below remain historical evidence.

The harness retains prior workflow, security, privacy and screenshot checks and scans populated resident/control/admin desks in both themes at desktop and 320 CSS pixels, including expanded administrator forms. It also scans translated Afrikaans/isiZulu resident desks at 320 pixels. WCAG 2.0/2.1 A/AA and 2.2 AA tags include colour contrast and target-size checks. Supplemental computed-colour checks verify form values, table captions and the metric gradient endpoints at a minimum 4.5:1 ratio when axe marks clipping/gradients incomplete. Additional checks cover keyboard order, focus outline/unobscured geometry, control dimensions, reduced motion, status roles, horizontal page overflow and a 720 CSS-pixel layout equivalent to 200% zoom on the 1440-pixel desktop. This viewport-equivalence check is distinct from manual browser text-only zoom. Full axe reports, including `incomplete` items requiring judgement, go to `$TMPDIR/browser-smoke/axe-*.json`; screenshots remain temporary by default.

Local verification passed **158 browser checks**, including **14 axe scans with zero A/AA violations**, with no CSP/runtime errors. The field/gradient contrast samples were at least **5.48:1** across both themes (full reports remain in the temporary QA directory). **24 new localization tests** verify server replies, every workflow template, exact translated consent capture, resource key/placeholder parity and unsafe isiZulu arrival promises; the focused existing AI/ElevenLabs/privacy regression run passed **209 tests**. The final round-7 handover records the whole-repository gate. All requests in the browser QA stay on the local synthetic server; provider clients use offline doubles.

## Manual release checklist and gaps

- Use Tab/Shift+Tab from the skip link through language, report fields, purpose/contact choices, lookup, chat and staff access; activate controls with Enter/Space. Confirm the order stays logical after changing view, role and municipality. Check focus after validation failures and after every generated case action.
- In Chrome and Firefox, test browser zoom at 200%, text-only zoom where supported, 320 CSS-pixel reflow and operating-system high contrast. Review nested scroll containers and wide audit/outbox tables with keyboard and magnification. Two-dimensional data tables may scroll within their own labelled region.
- With NVDA/Firefox, JAWS/Chrome and VoiceOver/Safari, confirm labels, headings, disabled controls, status/validation messages, chat updates and language pronunciation. Check that frequent operational refreshes do not overwhelm announcements.
- Check every light/dark state: hovered and selected queue items, validation, qualification warnings, expired certificates, shown-once tokens and provider degradation. Include municipal branding overrides and native date/time/select widgets.
- Have native speakers review all Afrikaans/isiZulu content, especially emergency guidance, privacy notices and status distinctions. Approve each changed translated notice/version with the Information Officer before resident use.
- Test the real SSO redirect, live ElevenLabs widget/private microphone flows and provider error states with assistive technologies after owner configuration. The offline client double cannot certify third-party accessibility. Captions/transcripts, call quality and isiZulu live voice remain owner/provider validation.

These assistive-technology combinations, text-only zoom, live provider surfaces, independent WCAG audit and native-speaker review remain **owner-pending**. No production accessibility certification is claimed. Success criteria and exceptions follow the [W3C WCAG 2.2 standard](https://www.w3.org/TR/WCAG22/), including [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) and [focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).
